# RenewalDesk — SQL Server only

## What the project does

You work on a support team for a subscription and fleet service. The database contains 1,200 **synthetic, English-language** historical support cases. Given a new question, a T-SQL stored procedure retrieves related cases and shows the original text and case ID so a human can inspect the evidence.

The scripts are designed for **SQL Server 2025 Developer and SSMS**. There is no Python, CSV import, paid API, or external model. The SQL vectors are transparent topic features built with rules. They are **not semantic AI embeddings**. The output is an extract from an existing case, not an AI-generated resolution.

## Run in SSMS

Connect to `localhost\SQL2025` with Windows Authentication. Open one `.sql` file at a time using **File > Open > File**, then press **F5**. Each script selects the `RenewalDesk` database itself.

| Order | File | What you should see |
| --- | --- | --- |
| 1 | `01_setup.sql` | Creates or reuses the database, table, schema, and two B-tree indexes. `SupportCasesTableId` should be a number. |
| 2 | `02_seed_cases.sql` | Builds 1,200 training cases with T-SQL. Expect `LoadedTrainingCases = 1200` and `SQL-topic-rules-v1-NOT-AI`. |
| 3 | `03_explore.sql` | Regex extraction and cleanup, JSON metadata, index queries, and exact vector distance. Press **Ctrl+M** before **F5** to include the Actual Execution Plan. |
| 4 | `04_fulltext_optional.sql` | Adds Full-Text Search when installed. If unavailable, the search procedure falls back to simple `CHARINDEX` matching. Initial Full-Text population may take a little time. |
| 5 | `05_search_procedure.sql` | Creates or updates `renewal.SearchCases`. Successful execution says `Commands completed successfully`. |
| 6 | `06_run_demo.sql` | Runs three example questions; each produces a source-backed excerpt and a ranked list of original cases. |
| 7 | `07_verify.sql` | Verifies 1,200 cases, 8 topics with 150 cases each, and runs a sample search. |

**Already used the earlier Python version?** The existing `RenewalDesk` table can be reused. Running `02_seed_cases.sql` **replaces the synthetic project rows whose `CaseId` is 1 through 1200**, including their vectors, with the English SQL-only dataset. Do not run the seed script in a production database or in a table containing real data. Rerunning scripts 01 and 02 in this dedicated training database is intentional.

## Ask a question

```sql
USE RenewalDesk;
GO
EXEC renewal.SearchCases
    @Question = N'Why does the fleet vehicle battery fail after charging?',
    @Keyword  = N'battery',
    @Top      = 5;
```

The first result set is an **extractive answer**: the text of the closest historical case. The second result set contains `SourceDocument`, `CaseId`, exact cosine `Distance`, `VectorRank`, `KeywordRank`, and the fused `RRFScore`. The `TextEngine` field tells you whether Full-Text or the `CHARINDEX` fallback ran. You can omit `@Keyword`: the procedure chooses a term from the recognized question topic.

## How retrieval works

1. The seed script classifies each case into one of eight topics: renewal, billing, login, outage, battery, performance, contract, or payment. It stores a 384-dimensional `vector` with exactly one topic coordinate set to 1.
2. `renewal.SearchCases` recognizes a known English term in your question using `LIKE`, generates the same type of topic vector in SQL, and ranks 30 cases by `VECTOR_DISTANCE('cosine',...)`. This is an exact calculation.
3. A separate branch finds text matches through `CONTAINSTABLE` and ranks them using its `RANK`, or uses `CHARINDEX` when Full-Text is missing.
4. The procedure merges the two ranked lists using Reciprocal Rank Fusion: `1/(60 + vector rank) + 1/(60 + keyword rank)` for whichever lists contain the case. It returns an excerpt and the top source documents.

Questions outside the eight recognized topics will return a clear error. A shared topic makes vectors equally similar, so the distance cannot assess nuanced meaning or the quality of an answer. This is a transparent learning prototype; real semantic search would require embeddings generated by a model and a suitable approach for generating query vectors.
